# Thread Pocket 原型

围绕「持续线索（Thread）」组织的个人事项工具：把当前认识、行动、探索方向、等待、笔记与日志放在同一个上下文里，
让中断之后重新回来时能立刻接上。

本仓库包含两个独立部分：

```
thread-pocket-ds/
├── DESIGN.md           产品设计文档（概念层级、信息组织、使用范式）
├── server/             后端：零依赖 Node HTTP 服务 + SQLite，可独立部署
│   ├── src/            db / repo / views / api / http / server
│   │   ├── auth/       自实现的 OAuth 授权服务器（DCR + PKCE + 刷新轮换）
│   │   └── mcp/        自实现的 MCP 服务（instructions 里内嵌 skill 说明）
│   ├── public/         内置 Web 控制台（复用同一套 API）
│   └── test/           79 个接口 / OAuth / MCP 测试
├── AUTH.md             鉴权与对外暴露设计
├── docs/deploy.md      反向代理与部署自检
└── macos/              macOS 客户端：SwiftUI，连接任意后端 URL
    ├── Sources/ThreadPocket/
    └── Scripts/build-app.sh
```

前后端通过 HTTP + JSON 通信。桌面端不内嵌任何业务逻辑的后端，只依赖一个可配置的服务器地址；
Web / 移动端可以复用同一个部署（`server/public/index.html` 就是一个现成的例子）。
Agent 通过 MCP 直接读写同一个工作区，鉴权与桌面端共用一套 OAuth。

## 快速开始

### 1. 启动后端

```bash
cd server
npm start                 # 默认 http://127.0.0.1:8787
```

首次启动会自动建立「工作 / 生活 / 学习」三个 Domain 和各自的收件箱。想要一份完整的演示数据：

```bash
npm run seed              # 写入演示数据（装修 / 工作 / 学习 / 生活）
npm run reset             # 清空并重建演示数据
npm test                  # 运行接口与视图测试
```

### 2. 运行 macOS 应用

```bash
cd macos
./Scripts/build-app.sh release     # 产出 dist/ThreadPocket.app
open dist/ThreadPocket.app
```

首次启动会看到连接引导：填写后端地址（默认 `http://127.0.0.1:8787`）并连接。
之后随时可以用 `⌘,` 打开连接设置修改地址、令牌与自动刷新频率。

### 3. 让 Agent 接入（MCP）

后端在同一个地址上提供 MCP：`http://127.0.0.1:8787/mcp`。
在客户端里填这个地址即可，**不需要再额外安装 Skill** —— 工具的用法说明会作为
MCP 的 `instructions` 随 `initialize` 一起下发。

```jsonc
// 例如 Claude Desktop / 其他 MCP 客户端配置
{ "mcpServers": { "thread-pocket": { "url": "http://127.0.0.1:8787/mcp" } } }
```

第一次连接时客户端会收到 `401` 与资源元信息挑战，随后自动完成
「发现授权服务器 → 动态注册 → 打开浏览器登录 → 授权 → 拿到令牌」。
授权范围是 `mcp:tools`，只能通过 MCP 工具读写，不能拿去调 REST API。

## 鉴权

服务同时是 OAuth 授权服务器与资源服务器，默认安全、本机好用：

| 部署形态 | 行为 |
| --- | --- |
| 本机、还没有账号 | 开放，起来就能用 |
| 本机、已有账号 | 需要登录（浏览器会话）或令牌；`⌘,` 里点「使用浏览器登录」一次即可 |
| 对外地址（设了 `THREADPOCKET_PUBLIC_URL`） | 所有请求都要凭证；本机豁免被强制关闭 |
| 绑定到非回环地址却没有任何鉴权 | **拒绝启动**，避免把个人数据裸奔到公网 |

要点：只接受公共客户端 + PKCE(S256)；令牌在库里只存哈希；刷新即轮换，
旧刷新令牌被重放会让整个令牌族作废；桌面端走 RFC 8252 的回环回调，
令牌存钥匙串。完整设计见 [AUTH.md](AUTH.md)，部署检查见 [docs/deploy.md](docs/deploy.md)。

## 功能范围

对齐 DESIGN.md 的实现情况：

| DESIGN 概念 | 桌面端实现 |
| --- | --- |
| Domain（关注范围） | 顶部领域 chip，可新建/改名/换色/删除；`全部` 表示跨领域 |
| Thread（可独立接续的一件事） | 左侧线索列表：标题、当前描述摘要、未结束事项计数、状态；支持归档 / 回收站 / 彻底删除 |
| 当前描述 | 详情顶部卡片，点击即改，保存后自动写入日志（保留变化前后） |
| 行动（待办 / 固定日程） | 计划日、截止日、固定时间与时长；完成、取消、重开、受阻标记 |
| 探索方向 | 独立分区，不进入待办计数、不进今天与行动；可「转为待办」或「放弃」 |
| 等待与阻塞 | 独立分区，可设跟进日；解除等待后回到日志；受阻的行动也汇总在这里 |
| 笔记 | 每个 Thread 一份自由笔记，自动保存（1.1s 防抖）或手动保存 |
| 日志 | 一条时间顺序；进展笔记用主要文字层级，新增/完成/改期等操作记录用更弱的颜色与更紧的间距 |
| 总览 · 今天 | 今天 / 已逾期 / 待重新安排 / 已过时间的日程，按关注原因分组，同一事项只出现一次 |
| 总览 · 行动 | 未结束的待办与日程，按 Thread 分组；`全部 / 有时间 / 无时间` + `不限时间 / 近 7 天` 筛选 |
| 总览 · 收件箱 | 聚合各 Domain 收集箱里的未结束事项，保留来源，可完成或移动到其他 Thread |
| 视图筛选 | Thread 模式保留 `全部 / 今天 / 近期 / 等待`；`日常视野 / 归档 / 回收站` 切换 |
| 搜索 | 顶部搜索框实时搜索线索与事项；`⌘K` 聚焦 |
| 草稿保护 | 当前描述或笔记未保存时切换线索，会先问「保存并切换 / 放弃修改 / 留在原处」 |
| 人与 Agent 共用语义 | 后端记录 `actor`，任何操作都留下可读日志，另一个参与者仅凭 Thread 就能理解现状 |
| Agent 接入 | MCP（Streamable HTTP）14 个工具 + `instructions` 内置 skill 说明；OAuth 授权，无需手工发令牌 |
| 登录 | 浏览器 OAuth（回环回调 + PKCE），令牌存钥匙串，过期自动用刷新令牌续期；也可填静态令牌给脚本用 |

### 交互约定

- 不使用 macOS 原生右键菜单：所有右键/`⌘点击`菜单都由应用自己绘制（`PocketContextMenu`），
  包括文本编辑区（剪切 / 复制 / 粘贴 / 全选 / 插入时间戳）。
- 不使用系统 toggle box：完成框是自定义绘制并带动画的 `PocketCheck`；分段控件、下拉菜单、
  日期选择器、确认框同样是自绘组件，动画统一走 `PocketMotion` 的 spring。
- 快捷键：`⌘N` 新建线索 · `⇧⌘N` 新建事项 · `⌘K` 搜索 · `⌘⏎` 记录进展 · `⌘R` 重新加载 · `⌘,` 连接设置。
- 断网时保留本地视图，顶部出现「未连接到后端」提示与重试入口；失败的写操作给出带重连按钮的提示。

## 架构

```text
ThreadPocket.app (SwiftUI)                 Web / 移动端（未来）
        │                                          │
        │  HTTP + JSON  /api/v1/*                  │
        └──────────────► server（Node，零依赖）◄────┘
                             │
                             ├── SQLite（data/thread-pocket.sqlite）
                             └── public/ 内置 Web 控制台
```

后端不假设客户端形态：所有视图（今天 / 行动 / 收件箱）都由服务端计算，客户端只负责呈现与提交意图。
这意味着新增一个 Web 或移动端客户端时，不需要重新实现「今天该显示什么」这类产品逻辑。

### 桌面端数据流

1. 启动或 `⌘R` 时拉取 `/api/v1/snapshot`，一次拿到 domains / threads / items / notes / logs。
2. 所有写操作走 REST，服务端在同一个事务里更新数据并追加日志，然后把受影响的 Thread 上下文返回给客户端。
3. 客户端用返回值整体替换该 Thread 的本地状态，因此界面与服务端始终一致。
4. 可选的自动刷新（30 秒 / 2 分钟）用于在其他客户端写入后保持一致。

## 后端部署

后端只需要 Node ≥ 22.5（用到内置的 `node:sqlite`，无第三方依赖）。

```bash
# 生产环境变量
PORT=8787
HOST=0.0.0.0                                  # 容器里通常用 0.0.0.0
THREADPOCKET_DB=/var/lib/thread-pocket/data.sqlite
THREADPOCKET_API_KEY=please-change-me         # 可选：设置后要求 Bearer 令牌

node src/index.js
```

部署形态可以是裸机 `systemd`、容器，或任何能跑 Node 的 PaaS；数据就是一个 SQLite 文件，
备份即复制文件。设置令牌后，健康检查与元信息接口仍然开放，其余接口需要
`Authorization: Bearer <token>`。

API 细节见 [server/README.md](server/README.md)。

## 已知边界

- 这是原型，不含账号体系与多端冲突合并；单用户、单后端。
- 应用未做公证签名，本地分发包使用临时签名，首次打开如被拦截可在「系统设置 → 隐私与安全性」中放行。
- 自动提醒、完整日历调度、团队协作不在 DESIGN.md 定义的范围内，尚未实现。
